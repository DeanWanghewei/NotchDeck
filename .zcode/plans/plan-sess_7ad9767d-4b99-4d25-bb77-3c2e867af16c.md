# 插件适配脚本剥离：GLM 解析随市场脚本独立更新（v0.22.0）

## Context

订阅插件的适配层（端点、响应解析）随供应商格式频繁变化（v0.21.x 六个版本全是），而它编译在主程序里——每次适配修改都要重装 App，且未签名 App 每次重装都触发 Gatekeeper“无法验证安全”。方案（已与用户确认）：把**适配层抽成 JavaScriptCore 沙箱脚本**，经插件市场目录分发下载，改脚本即可在应用内完成更新、不重装不重启；宿主层（账号/加密凭据/网络/SwiftUI/通知）保持原生。能力边界：脚本只能计算与解析——无网络、无文件、无进程、拿不到密钥明文（`{credential}` 由宿主注入请求），脚本 URL 经目录 sha256 校验、请求主机经原生白名单。Codex 的 CLI 编排本期不动，仍走原生解析。

**版本检测与更新节奏（用户已确认 A 档）**：打开插件市场页时若距上次目录检查 ≥1 小时则**静默自动刷新**（失败不打扰、不显示错误横幅），后台从不联网；手动「刷新目录」保留且失败提示如常；发现脚本新版后由用户显式点「更新脚本」，**成功后立即热加载并触发一次额度刷新**，当场生效。

## 架构

```
marketplace/scripts/subscriptions-glm.js   ← 适配脚本 v1.0.0（仓库维护，PR 即可更新）
        ↓ 目录声明 script{url,sha256,version}
打开市场页(≥1h)静默刷新 或 手动刷新 → 卡片显示"脚本 vX 已安装/可更新" → [更新脚本]
        ↓ PluginScriptClient（下载，仿 PluginCatalogClient：ephemeral/禁重定向/12-15s/256KiB）
PluginScriptStore（~/Library/Application Support/NotchDeck/Plugins/<id>/adapter.js + manifest.json，0700/0600，sha256 落盘与加载双校验）
        ↓ NotificationCenter(.pluginScriptDidUpdate)
SubscriptionQuotaModule 重载脚本源 + 立即 refresh() → 注入 parse 闭包
        ↓ GLMQuotaQuery.start(request:parse:)（请求模板也来自脚本，主机白名单强制）
JSContext（每查询新建，后台 delegate 队列）→ { plan, windows:[{title,usedPercent,resetsAtMs}] }
        ↓ 任一环节失败 → 回退内置 SubscriptionQuotaParser.glm + 设置页警告
```

## 实现步骤

**1. 目录 schema v2** — `Core/Plugins/PluginCatalog.swift`
- `validated()` 接受 `schemaVersion == 1 || == 2`（旧版 App 收到 v2 → unsupportedSchema → 保留旧缓存，优雅降级）
- `PluginListing` 增 `script: PluginScriptSource?`（`{ url: String, sha256: String, version: String }`）
- 校验：url 须 https + `raw.githubusercontent.com` + 路径前缀 `/DeanWanghewei/NotchDeck/`（新 `isRepositoryScriptLink`）；sha256 为 64 位小写 hex；version 可被 `PluginVersion` 解析

**2. 脚本下载与存储** — 新 `Core/Plugins/PluginScriptClient.swift`、`Core/Plugins/PluginScriptStore.swift`
- Client 照抄 `PluginCatalogClient` 的传输硬化（拒重定向、流式+响应头双重大小上限 256 KiB、无 Cookie/缓存），下载完成先比 sha256 再落盘
- Store：目录 0700、文件 0600、同目录临时文件原子替换；manifest 记 version/sha256/downloadedAt；读取时复验哈希，不匹配视为未安装；`uninstall(pluginID:)` 供排障

**3. 市场状态、自动检查与更新动作** — `Core/Plugins/PluginMarketplace.swift` + `UI/PluginMarketplaceView.swift`
- `scriptState(for:)`：`.none / .installed(v) / .updatable(当前→目录v)`（版本比较复用 `PluginVersion`）
- `refresh(automatic: Bool = false)`：automatic 失败不设 `errorMessage`（静默）、不更新 `lastChecked`；手动路径行为不变
- `PluginMarketplaceView` 的 `body.onAppear`：`lastChecked == nil || 距今 ≥1h` 且未在刷新时调 `marketplace.refresh(automatic: true)`
- `updateScript(for:)`：仅已安装插件、显式点击触发；成功 post `.pluginScriptDidUpdate`（object: pluginID）；失败保留现有脚本并提示
- 卡片 actions 区（`PluginMarketplaceView.swift:134-155`）加一行：脚本版本状态 + 「更新脚本/安装脚本」按钮 + 沙箱边界帮助文案；底部固定说明（:42）改为“解析脚本在应用内更新，无需重装；打开市场会自动检查（≥1 小时一次）”

**4. JSC 适配运行时** — 新 `Modules/Subscriptions/GLMScriptAdapter.swift`
- 纯函数入口：`request(from:)`（校验 host ∈ 白名单 `open.bigmodel.cn / api.z.ai / dev.bigmodel.cn`，headers 为字符串模板，提取 `{credential}` 占位）；`parse(source:body:now:)`（每调用新建 JSContext、exception handler 捕获、校验返回结构：windows 1…8 条、title 非空、usedPercent 有限 ≥0、resetsAtMs 有限 >0 或空）
- 契约：`adapter.request = {url, headers}`；`adapter.parse(bodyString) → {plan?, windows:[…]}`；脚本负责 unit/number 映射、nextResetTime 多形态、去重、周期命名（现有 Swift 逻辑移植为 JS）
- 任何失败抛 `SubscriptionQuotaError.invalidResponse` 由上层回退

**5. 查询与模块接线**
- `Modules/Subscriptions/SubscriptionQuotaClients.swift`：`GLMQuotaQuery.start(key:configuration:request:parse:completion:)`，request 默认现值（URL+Authorization），照 `configuration` 注入模式扩展；`.live` 不变
- `Modules/Subscriptions/SubscriptionQuotaModule.swift`：`start()` 时与收到 `.pluginScriptDidUpdate`（object == "subscriptions"）时重载脚本源并调 `refresh()` 立即用新脚本查询；GLM 闭包组装：脚本可用且未停用 → 脚本 request+parse，解析失败回退内置 parser 并置 `@Published scriptDegraded`；脚本 request 主机不合法 → 整体回退内置
- `SubscriptionQuotaPreferences`（`Modules/Subscriptions/SubscriptionAccount.swift`）增 `glmScriptDisabled: Bool = false`（走既有 ModulePreferences 持久化）
- `UI/Settings/SubscriptionQuotaSettingsView.swift` 增“解析脚本”Section：显示 脚本 vX（市场）/ 内置、回退警告、停用开关（仿"Codex CLI" Section 样板）

**6. 适配脚本本体** — 新 `marketplace/scripts/subscriptions-glm.js`（v1.0.0，与内置解析等价的 JS 移植）；`marketplace/catalog.json` 升 schemaVersion 2 并加 script 字段（sha256 用 shasum 生成后填入）；`project.yml` 测试 target 增该 js 为资源（真实脚本进测试，防“脚本改了测试没跟”）

**7. 测试**（`Tests/PluginMarketplaceTests.swift` + `Tests/SubscriptionQuotaTests.swift`）
- 目录：v2 带脚本解码通过；v1 兼容；非法脚本 URL/sha/版本拒绝；`listing(id:)` 构造器补字段
- 下载/存储：sha 不匹配拒装、落盘篡改后加载失败、原子替换、卸载
- 市场：mock 脚本 fetcher（仿 `CatalogFixtureFetcher`）驱动 安装→更新→失败保留；**自动检查：lastChecked ≥1h 触发且静默（失败无 errorMessage、不更新 lastChecked）、<1h 不触发、手动失败仍提示**
- JSC：真实脚本资源跑全形态 fixture（复用现有 GLM 解析测试数据）；JS 异常/坏结构/超窗数 → 回退内置；主机白名单拒绝；`{credential}` 不进脚本（断言 JS 收到的入参只有 body）
- 模块：脚本路径产出快照、收到更新通知后重载并立即 refresh、脚本损坏回退内置且 widget 正常、停用开关生效、脚本源不落凭据（并入 `withFixture` 泄漏断言）

**8. 文档**
- `marketplace/README.md`：原则修订（“启动不联网；打开市场且距上次检查 ≥1 小时静默刷新一次，失败不打扰”）、安全模型段（“不下载可执行代码；仅下载无 I/O JavaScriptCore 沙箱适配脚本，凭据宿主注入、网络宿主执行、sha256 校验、主机白名单”）、目录格式 v2 表、维护流程新增“改脚本 → PR → 用户打开市场即见更新、点按钮即生效，无需发版”
- `docs/subscription-quotas.md`：GLM 解析可由市场脚本提供、应用内更新与回退内置、停用入口
- `README.md`：插件脚本独立更新与自动检查说明；测试计数更新
- `AGENTS.md`：marketplace 行与关键锚点补脚本存储路径一行
