# GLM / ChatGPT · Codex 订阅额度

“订阅额度”是插件市场的可选插件，展示多个 GLM Coding Plan 和 ChatGPT · Codex 账号的订阅用量，不代表 API 现金余额或 ChatGPT 网页聊天消息上限。

## 展示与账号管理

在设置 → **插件市场** 中添加 **订阅额度**。首次启用显示添加账号入口；无账号时不访问凭据或网络。添加账号后直接显示真实用量，不提供预览或演示模式。旧版演示开关自动忽略，已有账号与别名保留。

“布局与展示”支持 **顶部常驻 / 标签页 / 底部常驻**，以及 **百分比长条 / 百分比圆环 / 紧凑长条**。长条与圆环均显示已用及剩余数字、周期名称，直接展示重置时间；服务未提供时间时明确说明，使用同一冷→暖色标。每个账号使用单行标题；长条每个额度一行，GLM 圆环合并为同心圆，外→内依次对应 5 小时、每周、工具调用，右侧逐行显示层级、周期、已用/剩余数字和重置说明，圆心不显示汇总值；缺失额度不补零，多于三项则分组展示。Codex 保持独立圆环，更多额度横向滚动。切换样式和位置不重新查询账号；旧版 `cards` / `compact` 配置继续有效。

组件设置 → **添加账号** 可多次添加 GLM 或 Codex。别名可留空，未命名时自动显示“GLM 账号 1”“Codex 账号 2”等名称；身份由内部稳定 id 区分，相同别名也不会串用数据。每个账号可以单独停用、编辑或移除，修改别名不重启查询。

删除账号会移除本软件保存的对应凭据，其他账号与原始 auth.json 不受影响。在市场中移除整个插件则只停止运行并保留配置和凭据，重新添加可恢复。

## 本地加密存储与旧版升级

凭据目录为 `~/Library/Application Support/NotchDeck/Data/SubscriptionCredentials/`。GLM 密钥与 Codex 登录按账号分别使用 CryptoKit 的 AES-256-GCM 加密，随机 nonce，认证附加数据绑定服务、账号 id 和格式版本，防止串用或篡改。目录权限为 0700，密钥、密文及锁文件为 0600；写入通过同目录临时文件原子替换，删除账号仅移除对应密文。

随机生成的 256 位主密钥保存为该目录中的 `master-key-v1`，不硬编码，不使用钥匙串，也不要求用户输入额外密码。这能避免凭据明文落盘，但能同时读取密钥与密文的同用户程序仍可解密；它不提供钥匙串的独立访问控制。备份和恢复需包含整个目录，不能只复制密文；主密钥损坏或丢失时会报错，不自动重建覆盖旧数据。

升级后保留旧账号与别名，**不自动读取、迁移或删除旧钥匙串条目**，避免授权弹窗。请编辑各账号，重新填写 GLM 密钥或粘贴登录 JSON 并验证保存一次。旧条目可由用户在系统“钥匙串访问”中自行清理。新保存、刷新和删除账号均只操作上述应用目录。

## GLM Coding Plan

添加账号时填写 Coding Plan 密钥，可选别名。每个密钥独立加密保存在应用 Data 目录，不写入 UserDefaults、日志或命令参数。编辑已有账号时，新密钥留空表示保留原密钥；替换时只取消该账号查询并清除其旧快照。

采用智谱官方 [glm-plan-usage 插件](https://github.com/zai-org/zai-coding-plugins/tree/main/plugins/glm-plan-usage) 的只读接口 `GET https://open.bigmodel.cn/api/monitor/usage/quota/limit`。固定中国区主机，禁用重定向与 Cookie，响应上限 256 KiB、最长 15 秒，不调用模型推理。

依照接口已确认的 `TOKENS_LIMIT` / `TIME_LIMIT` 和 `percentage` 显示“编码额度”/“工具调用”。根据 `unit=3, number=5` 识别“5 小时”、`unit=6, number=1` 识别“每周”，不依赖返回顺序；此映射参考公开 CodexBar Z.ai 实现及用户确认的双窗口含义。未知周期保留“编码额度”并按需编号，只对完整原始对象完全相同的数据去重。重置时间直接读取条目的 `nextResetTime`（已实证形态：epoch 毫秒数字与 RFC3339 字符串，兼容数字字符串与按秒计的值；依据 zai-org/ZCode、Raycast agent-usage、zai-rs 等公开实现的响应样本），字段缺失或无法解析时显示“服务未提供重置时间”，不估算、不调用模型推理、不解析 429 错误文本；完整周期以[官方用量页](https://www.bigmodel.cn/coding-plan/personal/usage)为准。未带凭据的探针返回 HTTP 200 + 业务码 1001，客户端同时检查业务结果，不将认证失败显示为零用量。

## Codex：粘贴 JSON、验证与独立保存

添加 Codex 账号时，直接在 **账号登录 JSON** 文本框粘贴完整登录信息，需包含 `tokens.access_token`。不填写文件路径，不打开文件选择器。仅支持 ChatGPT 订阅登录，API Key 登录不能查询订阅额度。编辑已有账号时，JSON 留空保留原登录；填写新 JSON 则验证后替换。

格式错误、缺少 token、不支持的登录方式、超过大小上限会立即给出具体说明，不联网、不覆盖已有登录。JSON 合法后再显示在线验证阶段；网络、超时、登录失效、CLI 缺失和保存失败分别提示。错误消息不包含 token 或粘贴原文；关闭编辑器后清空输入。

点击 **验证并保存** 后：

1. 校验粘贴的 JSON 和 ChatGPT token 基本结构，上限 256 KiB。
2. 将登录放入权限为 0700 的独立临时 `CODEX_HOME`，auth.json 权限为 0600；强制使用 `cli_auth_credentials_store="file"`，避免回退到当前 CLI 登录或其他账号的钥匙串。临时环境不复制原目录的配置。
3. 用临时 `codex app-server` 完成握手，查询 `account/rateLimits/read`。不创建聊天，不执行工具或调用模型；CLI 自身可能在初始化时读取官方模型/插件目录。
4. **额度验证成功后**，才把该账号登录保存到 NotchDeck 的独立加密文件，账号元数据另行持久化。失败或取消不会添加账号或替换已保存的登录。
5. 后续从本地加密文件恢复登录，在隔离环境中查询；CLI 刷新后的 token 保存回同一账号，临时目录随后删除。

因此，切换 Codex 当前账号、重启 NotchDeck，都不会改变已保存的账号。不保存文件路径，也不依赖源文件。重新粘贴 JSON 可以更新某个账号的登录；登录被撤销或过期且无法刷新时，会提示重新粘贴登录 JSON。

组件自动查找 Homebrew、`/usr/local/bin`、`~/.local/bin`、Codex.app / ChatGPT.app 常见 CLI 路径，也可填写可执行文件路径，路径不作为 shell 命令解析。旧版跟随本机 CLI 登录的账号会保留并标记；编辑它并粘贴登录 JSON 后才固定为独立保存的账号。

Codex 登录文件格式参考 [OpenAI 官方 Authentication 文档](https://developers.openai.com/codex/auth/)，额度协议见 [App Server 文档](https://developers.openai.com/codex/app-server/)。面板优先使用 `rateLimitsByLimitId.codex`，兼容旧版 `rateLimits`；周期来自 `windowDurationMins`，重置来自 `resetsAt`，不混入独立模型或代码审查限额。

## 刷新、迁移与验证边界

- 启用后每 5 分钟刷新；展开面板时距上次查询至少 60 秒才补刷新，也可手动刷新。最多同时查询三个账号，每个账号不重叠，单账号错误不阻断其他账号。
- 停用、移除、更换凭据会取消相应任务，旧回调不能覆盖新账号。失败保留该账号上次成功的数值及时间；首次失败不虚构 0%。
- CLI 查询硬超时 12 秒，输出限制 256 KiB，结束或取消后回收子进程和临时凭据目录。
- 旧版 GLM / Codex 开关自动迁移为账号；账号与别名继续保留，迁移过程不读取旧钥匙串；旧版凭据需要重新填写 GLM 密钥或粘贴 Codex 登录 JSON 一次。新账号凭据按 id 隔离，UserDefaults 仅保存别名、启用状态和登录是否已导入等元数据。
- 解析、隔离目录、原文件不变、删除源文件后恢复查询、token 轮换、多账号并发、别名与旧配置迁移均有固定数据或模拟 CLI 测试。测试不使用真实账号；目前尚未使用有效 GLM 密钥或 ChatGPT 订阅登录核验端到端实时数值。

## 额度消息提醒

在组件设置的“额度提醒”中开启，首次开启会申请 macOS 通知权限。已用阈值默认 **100%**，可设置为 **1–100%**，对所有启用账号的每个额度独立判断。达到或超过阈值时，系统通知显示账号、服务、周期、当前已用百分比与阈值。关闭提醒不影响额度采集。

同一模块运行期间，同一账号、额度周期和阈值只提醒一次；新周期或修改阈值后可再次提醒。没有重置时间时，用量降至阈值以下后重新布防；已经到期的数据和查询错误不触发提醒。投递失败在后续成功采样时重试。重启应用或移除再添加插件后，首次成功采样仍达到阈值可再次提醒。开启提醒时也会检查已有的未过期成功数据。

授权、投递、前台横幅和权限错误文案使用 Core 公共消息组件，插件不自行实现系统通知。提醒依赖采样周期，并非实时推送；横幅能否弹出仍取决于系统通知设置与专注模式。无宿主测试使用替身验证触发和去重，不发送真实系统通知。

圆环样式中，同服务账号按原顺序两两配对，服务组按首次出现顺序排列。内容宽度至少 428pt 时每行两张卡片（最小 210pt、间距 8pt），奇数个账号的末项单独占一行；窄窗口回退单列。双列 GLM 卡片采用上方同心圆、下方明细；双列 Codex 采用纵向独立额度圆环，更新时间保留在卡片底部。长条与紧凑长条维持单列。

展示动画使用首次 0.2 秒淡入、账号增删 0.2 秒布局过渡、用量图形 0.35 秒缓动；数字始终显示实际读数，不使用循环动画。开启系统“减少动态效果”时关闭上述动画，直接呈现结果。
