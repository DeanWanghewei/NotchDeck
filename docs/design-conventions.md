# 设计约定：颜色与数据展示（项目约束）

> 适用范围：系统监控（CPU / 内存 / 磁盘 / 电池 / 网络）、自定义热力图，以及今后新增的**任何**指标展示。
> 本文是项目约束而非建议：新增或修改监控类 UI 必须遵循；实现与本文冲突时，要么改实现、要么先修订本文。
> 历史沿革：v0.19 引入悬停明细时确立了本套约定（此前 CPU 采用红绿灯式配色、热力图低值档过浅，均已按本约定重做）。

## 1. 颜色规范

### 1.1 连续负载 → 冷→暖色标（HeatScale）

连续型指标（CPU 占用等）一律使用 `UI/UIHelpers.swift` 中的 `HeatScale`，**禁止**红绿灯式（绿=好 / 橙=警告 / 红=危险）配色——占用高低不是"好坏"，是"冷热"。

- 语义：低负载 = 冷色（"围观核"冷蓝），高负载 = 暖色（"干活核"转红），与热力图直觉一致。
- 停靠点（sRGB，线性插值）：

| 负载 | 颜色 | 分量 |
|---|---|---|
| 0.00 | 蓝 | (0.30, 0.56, 1.00) |
| 0.30 | 青 | (0.10, 0.80, 0.90) |
| 0.55 | 绿 | (0.20, 0.80, 0.35) |
| 0.75 | 黄 | (0.98, 0.72, 0.12) |
| 0.90 | 橙 | (0.98, 0.45, 0.10) |
| 1.00 | 红 | (0.93, 0.20, 0.16) |

- 附带规则：
  - **数值文本只在暖区（≥0.70）跟着条着色**，冷区保持次要灰（`secondary`）——避免满屏彩色数字造成噪音；黄色小字在浅色背景可读性差，是阈值取 0.70 而非 0.55 的原因。
  - 最值强调（如"最忙核"）用**加粗**，不额外换色。
  - 停靠点是回归测试的一部分（`testHeatScaleRunsCoolToWarmWithExactStopsAndMidpoints` 断言端点与中点插值）；调整停靠点必须同步改测试与本文表格。

### 1.2 离散分类色（内存构成，近似活动监视器）

分类构成用固定分类色，与负载冷暖语义无关，同一语义跨视图必须一致：

| 类别 | 颜色 |
|---|---|
| App 内存 | 蓝 `.blue` |
| 联动（Wired） | 橙 `.orange` |
| 已压缩 | 黄 `.yellow` |
| 已缓存 | 绿 `.green` |
| 交换 swap | 紫 `.purple` |

- 构成条统一 `opacity(0.85)`、高 5pt Capsule。
- 不确定/未启用的值显示占位文字（如"未启用"），不显示 "Zero KB" 之类的伪数值。

### 1.3 阈值警示色

- 用量占比 **> 0.85** 用橙色警示（StatCard 主条、卷用量条）；内存卡等常规条保持主题渐变。
- 热压力 fair → 橙、critical → 红（热压力行）。
- 约束：警示阈值全项目统一 0.85；警示只作为"例外"出现（单条变色 / 描边 / 背景提示），不得改变常规梯度本身。

### 1.4 自定义热力图（单色深浅 + 失败态）

- 数值档位：绿色 5 档透明度 `[0.22, 0.42, 0.62, 0.82, 1.0]`。最低档必须在深浅两种面板上**清晰可见**（历史教训：0.15 档几乎消失）；最高档为实色。档距均匀。
- 失败样本（命令非 0 退出 / 超时）：**实色红**（`Color.red`），必须与任何数值档位一眼区分。
- 约束：**失败色不得与"最高值"颜色相同**。若未来热力图改用冷暖色标（高值趋红），失败态必须换区分手段（描边 / 斜纹 / 形状），不能只靠颜色。
- 图例（低 → 高 → 失败）与实际格子颜色共用同一组定义，禁止各自维护。

### 1.5 通用颜色约束

- 任何配色必须在**深浅两种外观**下验证（方法见 §3 验证流程）；冷色在浅色背景、暖色在深色背景都要可读。
- 语义色仅用于数据本身；交互状态（悬停 / 选中 / 固定）统一用 `accentColor` 描边与 pin 角标，不占用冷暖语义。
- 颜色定义集中放在共享处（`HeatScale`、`CustomHeatmapView.levelOpacities/failureColor`），禁止在视图里内联散落魔数颜色。

## 2. 数据展示规范

### 2.1 指标行式明细（CPU 每核 / 内存构成共用结构）

每行固定三段：

```
[标签 固定宽度·左对齐] [用量条 弹性宽度·Capsule 5pt] [数值 固定宽度·右对齐·monospacedDigit]
```

- **百分比必须直接显示数字**：条表达趋势，数字才是读数。不允许只画图形不给数字。
- 标签用可自解释的中文名（"核心 N" / "能效 N" / "App 内存"…），不采用需要背景知识的代号（如 E1/E2——用户不知道 E 是 efficiency）。
- CPU 每核两列网格排布（核数 > 16 自动收紧为 3 列，防止明细过长）；内存构成单列。
- 数值格式统一走 `ByteFormat`：字节数 binary countStyle、速率带 `/s`、百分比取整。
- 差分类数据（每核 CPU）首个采样周期无基线：显示"采样中…"占位，不得显示 0%（误导性读数）。

### 2.2 悬停明细 + 点击固定（交互约定）

- 悬停指标卡即在其**下方**展开明细；鼠标离开"卡片行 + 明细区"整体区域才收起（卡片间空隙、移入明细区本身都不触发收起，避免闪烁）。
- 点击卡片固定 / 再次点击取消固定；固定时显示 pin 角标与 accent 描边；固定期间悬停其他卡片不抢占内容。
- 明细底部始终保留固定操作的提示文案（发现性）；收展动画 0.2s ease。

### 2.3 数据采集约束（探针实证，随代码注释同步）

- 每核 CPU：`host_processor_info` + **`PROCESSOR_CPU_LOAD_INFO`**（注意：该接口不接受 `HOST_CPU_LOAD_INFO`——那是 `host_statistics` 的聚合 flavor；macOS 27.2 实测）。
- P/E 核划分：`hw.perflevel0.logicalcpu`，性能核在逻辑编号前段（M1 Pro 实测）；sysctl 无该键（Intel 等）→ 全部按编号展示，不区分。
- 内存构成：`vm_statistics64`（active/wire/compressor/inactive+speculative），"已用 = App + 联动 + 压缩" 近似活动监视器。
- 挂载卷：`NSFileManager` 卷枚举（iStat 走 Disk Arbitration，这是公开等价物），跳过隐藏挂载点，根卷在前，最多 6 卷。
- GPU / 风扇 / 温度：当前 macOS 已移除用户态接口（IOReport 框架删、SMC 协议变，26 与 27.2 两轮探针实证），恢复前**不得**引入私有框架兜底。

## 3. 变更与验证流程（硬性要求）

1. 改颜色 / 档位 / 停靠点 → 必须同步：对应回归测试、本文、README 功能表描述。
2. 新增指标展示 → 必须套用 §2.1 行式明细结构，配色按 §1 选择（连续负载 → HeatScale；离散类别 → 分类色；失败态 → 与任何值色可区分）。
3. 验证 = 全量测试通过 + 深浅两版窗口自渲染截图（`NSHostingView` + `cacheDisplay` 导出 PNG，不依赖屏幕录制权限）目检确认。
4. 新增数据源 → 先写探针脚本实证接口可用性与数据布局，结论写进代码注释，差分 / 解析逻辑做成纯函数并配回归测试。

```bash
xcodegen generate
xcodebuild -project NotchDeck.xcodeproj -scheme NotchDeck \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO test
```
